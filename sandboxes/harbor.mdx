Thunder maintains a [fork of Harbor](https://github.com/Thunder-Compute/harbor) with a `thunder` environment. Set up your API token with the [Sandbox quickstart](/sandboxes/quickstart), then install the fork:

```bash
uv tool install "harbor[thunder] @ git+https://github.com/Thunder-Compute/harbor.git"
```

Pass `--env thunder` to any run:

```bash
harbor run -d terminal-bench@2.0 -a claude-code -m <model> --env thunder --n-concurrent 32
```

Dockerfile and image tasks run natively in a sandbox, and Compose tasks run Docker inside a sandbox VM. Task network policies and GPU requests (`gpus`, `gpu_types` of `H100` or `A100`) are supported.

## Environment kwargs

Pass with `--ek key=value`:

| Option | Description |
| --- | --- |
| `gpu_type` | Override the task's GPU type. |
| `vm_cpus`, `vm_memory_mb`, `vm_storage_mb` | Size the VM independently of task limits (even vCPUs ≥ 4, ≥ 16 GiB memory, ≥ 18 GiB storage). |
| `sandbox_timeout_sec` | Maximum sandbox lifetime. No limit by default. |
| `sandbox_id`, `existing_sandbox_name` | Reuse an existing sandbox. Harbor won't terminate it. |
| `registry_username`, `registry_password`, `registry_server` | Private registry credentials. |

Sandboxes kept with `--no-delete` are billed until terminated, so pair it with `sandbox_timeout_sec`. See [pricing](https://www.thundercompute.com/pricing#sandboxes).
